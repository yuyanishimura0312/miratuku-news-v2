ANSWER 検証レポート 01 — UPRプレスリリースと kaken_researchers の照合

実機検証 | 2026-05-16 | esse-sense AWS開発DB × ミラツク UPR (大学プレスリリースDB)

1. 検証の目的

ミラツクの大学プレスリリースDB「UPR」（u-presscenter.jp 由来、41,760件規模）に蓄積される研究成果の発信内容と、esse-sense AWS開発DB（MySQL）の研究者マスタを連結できれば、プレスリリース発信から研究者の業績・所属・科研費・研究テーマまで一気通貫で参照可能になる。本検証では、UPRの本文・タイトルに埋め込まれた研究者の固有名詞を抽出し、esse-sense側の kaken_researchers（235,521件）に対して名前ベースで照合できるかを実機検証した。

結論: 名前ベースの単純照合で 72.5%（37/51） がマッチ。抽出ノイズを除いた実質マッチ率は85%超に到達する見込み。さらに重要な発見として、esse-sense MySQL の kaken_researchers.id が PostgreSQL の researcher_vectors.researcher_id と一致する結合キーであることを確認。

2. 方法論

UPRに蓄積されたプレスリリースの本文（excerpt列）とタイトル列から、研究成果の発表という性質上必ず含まれる「氏名＋役職」というパターンを正規表現で抽出した。具体的には漢字2〜7文字の氏名直後に「教授／准教授／助教／講師／研究員」のいずれかが続くパターンを探索し、UPR 300件のサンプルから51名のユニークな研究者候補を得た。続いてこれらを esse-sense MySQL の kaken_researchers テーブル（235,521件、KAKEN科研費DBから取り込んだ研究者マスタ）と name 列で内部結合した。

3. マッチング結果

51名の抽出候補のうち37名（72.5%）が完全一致し、所属機関名・職位・研究テーマ5キーワード・科研費プロジェクトIDなどの完全プロファイルを取得できた。マッチしなかった14名の多くは抽出側の正規表現ノイズに起因しており、「鴨川仁特任」のように接尾辞が混入したケース、または「佐竹 教授」のように姓のみで文脈が必要なケースであった。抽出規則を「役職トークンの直前・最大4文字」に限定すれば、これらの大半は救済可能で実質的なマッチ率は85%超に到達する見込みである。

4. 結合キーの重要な発見

実機検証の過程で、esse-sense の研究者マスタを esse-sense MySQL と esse-sense PostgreSQL（ベクターDB）の双方で照合する場合、結合キーの選択を誤ると別の研究者が返ってくることが判明した。正しい結合は kaken_researchers.id = researcher_vectors.researcher_id であり、一見類似する ess_researcher_id（esse-sense 内部ユーザーID）を使うと別人にヒットする。

たとえば ess_researcher_id = 914 は MySQL では「高橋 嘉夫（東京大学）」を指すが、PostgreSQL の researcher_vectors では「杉山 雄一（城西国際大学）」が返ってくる。これは ess_researcher_id が esse-sense 内部の追加されたカラムであり、ベクター生成時には kaken_researchers のプライマリキー（id）を採用しているためである。

正しい結合キー: kaken_researchers.id = researcher_vectors.researcher_id（ess_researcher_id ではない）

5. 構築可能な3段パイプライン

この結合キーの確定により、UPRプレスリリースを起点とした3段の研究者プロファイリングパイプラインが構築可能となった。第1段で UPR の本文・タイトルから研究者氏名を抽出し、第2段で MySQL の kaken_researchers から構造化メタデータ（所属異動履歴・論文・科研費プロジェクト・研究テーマ）を取得し、第3段で PostgreSQL の researcher_vectors から1536次元の意味ベクターを取得して pgvector の HNSW インデックスで類似研究者を TopN 抽出する。

6. 用途と今後の拡張

このパイプラインは次のような応用を可能にする。UPR新着プレスリリースに対する自動研究者プロファイル付与（バッチ処理）、企業R&Dプレス（SGRD）→大学側の関連研究者・科研費プロジェクトの提案生成（産学連携マッチング高度化）、プレスリリース本文のベクター化→KAKEN登録 938K研究者から類似研究者の意味検索、などである。

次のステップとしては、（a）抽出正規表現の改善で実質マッチ率85%超へ、（b）UPR本体42,219件への大規模適用、（c）SGRD・SGPRへの同じパイプラインの横展開、（d）SGRDで言及される研究者と大学の自動連結による産学連携シードリストの自動生成、が考えられる。
