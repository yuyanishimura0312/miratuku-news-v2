ANSWER 検証レポート 03 — 論文情報の取得粒度

実機検証 | 2026-05-16 | kaken_researcher_products 10,504,387件 / 主要カラム充足率の実測

1. 検証の目的

esse-sense AWS開発DBから論文・研究業績情報をどの程度の粒度で取り出せるかを明らかにし、用途別の適性を判断するための実機調査を行った。前回までの検証で UPRプレスリリースからの研究者照合パイプライン（72.5%マッチ率）と時系列情報の所在（4層構造）が確認できていたが、論文単位での情報取得についてはより具体的な粒度把握が必要であった。本検証では kaken_researcher_products の全カラムについて、サンプル100,000件で空文字列とNULLを除外した実質充足率を計測した。

結論: タイトル 99.8%・著者 98.4%・出版日 96.6% は完備。一方で抄録 8.3%・英文タイトル 0.3%・出版社 3.3% と極端に少なく、DOI／arXiv ID／全文PDF／被引用数はカラム自体が存在しない。「研究者ベースのプロファイリング基盤」として設計されており「論文ベースの引用分析基盤」ではない。

2. データの規模と性質

kaken_researcher_products は KAKEN科研費DB から取り込まれた研究業績一覧であり、約1,050万件のレコードを保持している。1レコードが1件の業績（論文・学会発表・書籍章・特許・報告書など）に対応し、kaken_researcher_id 列で研究者マスタ（235,521件）と多対多関係を持つ。研究者あたりの業績数は実例で9〜357件と大きくばらつくが、中堅以上の研究者では数十〜数百件が標準である。

3. 取得できる項目の充足率

100,000件のサンプリングで主要カラムの充足率を測定した結果、項目によって大きな差があることが判明した。タイトル（title、和文）は99.8%、著者リスト（creator_name、カンマ区切りテキスト）は98.4%、出版年月日（publication_date）は96.6%と、論文の基本3点はほぼ完備されている。一方、英文タイトル（title_en）は0.3%のみと極めて低く、英文書誌情報を主軸とした分析には別ルートが必要である。

4. 業績の種別構成

充足率の組み合わせから業績の種別を推定すると、conference_locationが埋まっているレコードが約35%（学会発表に相当）、source+volumeの両方が埋まっているレコードが約23%（ジャーナル論文に相当）、それ以外の約42%は書籍章・報告書・特許など多様な業績タイプであると考えられる。研究者プロファイリングにおいて「ジャーナル中心の発信スタイル」「学会発表中心の発信スタイル」を判別する材料として活用できる。

業績種別判定条件構成比
学会発表conference_location が非空約35%
ジャーナル論文source かつ volume が非空約23%
その他（書籍章・報告書・特許等）上記いずれにも該当せず約42%

5. 取得できないもの

明示的に確認した不在項目として、DOI・arXiv ID・ISBN といった外部識別子が無く、全文PDF・全文テキストへの直接リンクも保持されていない。被引用数・インパクトファクター・h-index（論文単位）といった citation metrics も欠如している。論文単位のキーワードタグも無く、キーワード情報は研究者単位の related_tags / industrial_tags / social_tags 列にのみ存在する。最後に、DB import 時期の関係で2024年8月以降の最新論文は反映されていない可能性が高い。

これらの欠落は、esse-sense DBが「研究者ベースのプロファイリング基盤」として設計されており、「論文ベースの引用分析基盤」としては設計されていないことを示している。引用ネットワーク分析や全文検索を行いたい場合は OpenAlex / Semantic Scholar / J-STAGE などの外部APIとの連携が必要である。

6. 実例：高田広章教授（id=55500）の業績データ

2023年1月1日付の「路車協調に向けた物標情報提供のためのデータフュージョンシステム」は、タイトル・著者（川田福和, 丈達生伍, 山田峻也, 渡辺陽介, 佐藤健哉, 高田広章）・日付が揃っているが source/volume/issue/page は NULL であった。一方、2022年の英文論文「Efficient Access Method for Multi-access Edge Servers in Dynamic ...」は source（International Journal of Intel...）と volume・pages を保持していた。このように同一研究者でも業績によって書誌情報の充足度に差がある。

著者情報はORCIDなどの一意IDではなく、カンマ区切りのテキストとして保存されており（例：「山口 晃広, 島田 秀輝, 伊藤 信一, 石原 直樹, 本田 晋也, 佐藤 健哉, 高田 広章」）、共著者間の研究者IDレベルでの自動紐付けは行われていない。共著ネットワーク分析を行う際は、テキストマッチで再連結する必要がある。

7. 用途別の適性

実機調査の結果、論文情報の取得は次のような用途に適している。第一に「誰がいつ何を書いたか」の業績一覧取得には十分（タイトル・著者・日付が98%以上完備）。第二に長期キャリアにわたる論文系列分析（30年分・publication_dateで時系列追跡可能）。第三に学会発表とジャーナル論文の大まかな分類（conference_location の有無で判別）。第四に研究者プロファイリングと類似研究者探索（pgvectorの研究者単位ベクター活用）。

一方、適していない用途として、論文間の引用ネットワーク分析（被引用データ無し）、ジャーナル名・巻号でのレファレンス書誌検索（半分程度のみ）、論文単位の抄録テキストでの意味検索（8.3%のみ）、DOI起点での外部DB連携（DOI無し）、英文タイトルベースの国際比較（0.3%のみ）が挙げられる。

8. 補助テーブル

researcher_external_articles（1,371,708件）は研究者ページから外部論文へのリンクを link 列で保持しており、researchmap_id とも紐付いている。kaken_researcher_reports（116,355件）は科研費年次報告書を、kaken_researchers.report_pdf_url は各研究者の科研費総括レポートPDFへのリンクを保持している。これらを組み合わせれば、KAKEN内の業績データ＋外部論文リンク＋研究者レポートPDFという3層構造で研究者プロファイルを構築できる。
