5.4 refinement 起動条件 + R3 失敗時の根本原因分類

仮に C-6 sentinel が CONDITIONAL APPROVAL もしくは REJECT を出した場合、refinement-coordinator が最大 3 ラウンドの修正サイクルを実施する。

  • R1 起動条件: doc-verify Minor 残存（軽微）— 例: 用語表記揺れ、軽微算術修正
  • R2 起動条件: doc-verify 重大事項残存（中等度）— 例: 図表配置ミス、構造的記述漏れ
  • R3 起動条件: sentinel REJECT（致命的）— 例: Phase A 数値継承の根本的崩壊、四位一体マスター図の構造的不整合

R3 失敗時の根本原因分類:

  • Spec 起因 → Phase C briefing 修正: C-6 briefing 必須項目の解釈不一致が根本原因 → briefing 改訂
  • Design 起因 → Track 内設計見直し: 四位一体マスター図の設計案が不適切 → C-6 内設計見直し
  • Implementation 起因 → Lead 担当者交代: 特定数値の継承ミス、用語統一不徹底 → C-6 リード交代もしくは追補
