## プロジェクト位置づけ

## 品質ゲート方針（Phase B 同様の三層）

### Layer 1: doc-verify（独立検証）
各 Track 完了後、以下 4 カテゴリで機械的・独立検証:
1. スナップショット不整合（Phase B 数値継承の正確性）
2. ハルシネーション（DB 実値との照合）
3. カバレッジギャップ（briefing 必須項目への対応）
4. チーム間不整合（Phase A/B 値との連続性）

### Layer 2: sentinel（最終ゲート、VETO 権付き）
doc-verify 通過後の最終判定。CONDITIONAL APPROVAL の場合は refinement 要求、REJECT の場合は最大 3 ラウンドの refinement-coordinator サイクル。

### Layer 3: refinement-coordinator（修正サイクル）
最大 3 ラウンド。R3 失敗時の根本原因分類:
- Spec 起因 → Phase C briefing 修正
- Design 起因 → Track 内設計見直し
- Implementation 起因 → Lead 担当者交代
