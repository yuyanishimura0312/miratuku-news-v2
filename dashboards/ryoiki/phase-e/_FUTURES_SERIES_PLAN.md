## 1. 企画概要

### 1.1 連載タイトル候補

第一候補（推奨）: **「未来のかたち ― 学術が未来予測の前提に出会うとき」**（英: Futures-no-Katachi: When Academia Meets the Foundations of Foresight）

副候補:
- 第二候補: **「未来のかたち ― 71 の問いと 140 の偉業から」**（副題に Phase B/C 確定値を埋め込む構成）
- 第三候補: **「ふたつの未来 ― 装置が応答する未来と、まだ応答できない未来」**（Phase B 戦略的空白 13 問の構造を主軸に置く）
- 第四候補: **「物語転換期の見取り図 ― 100 の問いと、その担い手」**（C-5 第 5 類型「翻訳者型」を前面化）

シリーズ系の整合: kurashi-no-katachi（暮らし）/ 事業のかたち（経営・事業）/ 変化のかたち（社会変容の型）/ いとなみのかたち（生活営為）の 4 連載に対し、本連載は **「未来のかたち」** として「フォーサイト × 学術」を担う第 5 シリーズの位置を取る。語尾「のかたち」を踏襲し、Translational Editor 型ワークフローの 5 番目の系として設計する。

### 1.2 連載の狙い

第一に、ミラツク領域策定プロジェクト Phase A/B/C/D で集積した 31+ 自社 DB を横断する知識基盤を「学びのコミュニティ Futures」に向けて段階公開し、参加者にとって読みながら考える素材として運用する。第二に、Phase B 71 独立問い + Phase C 140 偉業 + 担い手 5 類型 を一話単位で読み解ける形に翻訳し、フォーサイトを「他人事」から「自分事」へ橋渡しする。第三に、ミラツクの独自貢献である「対等な探究者」「知識運動体」「暗黙知の AI 形式知化」を学術と結びつけ、コミュニティ参加者の問い直し力を育てる。

具体的には次の三つの読書効果を目指す。第一に、未来予測（フォーサイト）に対する読者の構えを「予測を受け取る側」から「問いを差し出す側」へ反転させる。第二に、Phase A 9 トラック解析で発見された「2030 近傍 56.4% 集中構造」「values 領域 0.45% 空白」「グローバルサウス 0.10% 空白」といった構造的偏在を、読者が自身の文脈で再発見できる視点を提供する。第三に、Phase C 140 偉業の系譜接続（過去 → 現代 → 未来）を読み解くことで、参加者が自身の関わるアクションを長い時間軸の中に位置づけ直す。

### 1.3 全体構造

連載は 5 PART × 20 話 = **100 話** で完結する。各 PART は Phase A-D の主要発見群と対応し、PART 内 20 話は **Phase B 71 問 + Phase C 140 偉業 + 担い手 5 類型 + メタ自己診断** の四つの軸が交差して構成される。

```
PART I    現在地 ―― 物語転換期の見取り図          20 話
PART II   問いを問う ―― 71 の独立問いと 4 層構造    20 話
PART III  系譜の偉業 ―― 過去・現代・未来の連結      20 話
PART IV   担い手の像 ―― 第 5 類型「翻訳者型」を中軸に  20 話
PART V    未来のかたち ―― 2070-2100 の長い時間軸へ  20 話
合計                                              100 話
```

PART I は near (2026-2035) 帯の足場を読者に与え、PART II-IV は mid (2036-2055) 帯の構造解読、PART V は far/very-far (2056-2100) 帯の射程拡張を担う。第 50 話と第 100 話は本連載のメタ自己診断話（DQ-05 G-V03 由来）として節目に配置する。

連載通底の物語は次の三段階で立てる。第一段階（PART I-II）「現在地と問いの構造を共有する」、第二段階（PART III-IV）「系譜と担い手を媒介に行為と人物を読み込む」、第三段階（PART V）「2070-2100 の射程で再び問いを差し出す」。これは Phase A の 4 ホライズン（2030 / 2050 / 2070 / 2100）の段階的拡張と整合する設計である。

## 3. 各話のフォーマット仕様

### 3.1 文字数と構成

各話は **本文 1,500 字 + 学術の視点 400 字 + 出典一覧** の三段構成を厳守する。先例 kurashi-no-katachi（1,200-1,300 字）/ 事業のかたち（1,500 字）/ 変化のかたち（1,500 字）/ いとなみのかたち（1,500 字）のうち、最も長い 1,500 字構成を採用する。これは本連載が学術濃度の高い PART II/III を含むため、kurashi-team の 1,200-1,300 字では論理展開が窮屈になるという判断による。

```
1. 導入（200 字）  ― 読者の現場・身近な感覚から入る一段落
2. 主軸（700 字）  ― 該当する問い／偉業／担い手の本筋
3. 学術の補助線（400 字） ― 学術 DB から引いた周辺概念で構造を見せる
4. 結語と問いかけ（200 字）― 読者への問いを差し戻す
=== 本文小計 1,500 字 ===

5. 学術の視点（400 字）  ― 別エージェントが書く、学術 DB の活用補足
6. 出典一覧（DOI/書誌情報の箇条書き、本文外）
```

導入は kurashi-writer の冒頭多様化原則を継承し、二人称（「あなた」「私たち」）の使い方は PART I/V を中心に、PART II-IV は三人称的記述を多用する。学術用語は最小限にとどめ、必要な術語は学術の視点ボックスで補完する。

### 3.2 「学術の視点」400 字ボックスの設計

学術の視点ボックスは kurashi-deeper / keiei-deeper / itonami-team で実証された DEEPER 設計の系を継ぐ。本連載では「フォーサイト × 学術」という性質に合わせ、次の三軸でボックス内容を立てる。

```
A. 概念史の位置づけ  ― 該当概念がどの学術系譜から立ち上がってきたか
B. 最新動向         ― 直近 2-3 年の論文・データから補強される現代性
C. ミラツク DB との接続 ― 31+ DB のどこに格納されているか、どう引けるか
```

400 字内訳の目安は A 150 字 + B 150 字 + C 100 字。書籍タイトル・著者引用は出典一覧に集約し、ボックス内では「『場所性』概念は 1970 年代の人文地理学（イーフー・トゥアン）に源流を持つ」のような短い導入で統合する。

### 3.3 出典一覧

各話末に最低 3 件・上限 8 件の出典を提示する。出典は次の四系統の混合で構成する。

```
1. 学術論文（DOI 必須、Semantic Scholar / DOI.org で検証）
2. ミラツク DB（DB 名 + テーブル + record_id）
3. ミラツク Phase A/B/C/D 成果物（HTML 内見出しまで明示）
4. 一次資料（先住民資料・条約原文・憲法条文等）
```

DOI と URL は別エージェントの編集者が二段階検証を実施する（kurashi-editor の引用検証フローを継承）。

## 5. 章立て案（PART 構成、シリーズ全体の物語）

### 5.1 シリーズ全体の物語アーク

連載 100 話は次の 5 段階アークで読まれる。

第一段階（PART I 第 1-20 話）「現在地に立つ」: 読者が物語転換期の只中にいる感覚を、Phase A の実数値（FK 56.4% / values 0.45% / グローバルサウス 0.10% / Track 6 言説-実績ラグ）で確かめる。本連載が「未来予測の本」ではなく「未来予測を問い直す本」であることをこの段階で示す。

第二段階（PART II 第 21-40 話）「問いを問う」: 71 独立問いを TOP10 → 4 層 → 戦略的空白の順で読み解く。読者は本連載の中盤で「問いの密度」に直面する。最も理論密度の高い 20 話となる。

第三段階（PART III 第 41-60 話）「系譜を読む」: 5 系列の偉業を過去 → 現代 → 未来の縦軸で連続展開する。第 50 話の自己診断話で連載半ばのリズムを切り替える。読者は系譜の積み重ねを通じて、現代の偉業が 700 年・1000 年単位の長い時間軸に乗っていることを実感する。

第四段階（PART IV 第 61-80 話）「担い手の像」: 4 軸構造化と第 5 類型「翻訳者型」を中軸に、産業革命期から物語転換期への担い手主役交代（Mediator 過剰要求度 9.0 倍）を読む。読者は担い手を「自分」に重ねて読む段階に入る。

第五段階（PART V 第 81-100 話）「未来のかたち」: 2070-2100 の射程に拡張し、19 次元の外側 64 件・xeno-ethics・三項経済・UBI 二系統・神話社会 2050 などを読み解く。第 100 話で連載全体を自己診断的に閉じる。

### 5.2 各 PART のテーマと読書効果

```
PART I  「現在地」     → 読者は時代の構造に直面する
PART II 「問いを問う」 → 読者は 71 問の台帳を共有する
PART III「系譜を読む」 → 読者は系列の縦軸を歩く
PART IV 「担い手の像」 → 読者は担い手の像を自分に重ねる
PART V  「未来のかたち」→ 読者は射程を 2100 年に伸ばす
```

### 5.3 連載貫通の三軸

第一軸: **時間軸**（near 2026-2035 → mid 2036-2055 → far 2056-2080 → very-far 2081-2100）。PART I が near、PART II/III/IV が near-mid、PART V が far/very-far に重みを置く。

第二軸: **層軸**（メタ → 規範 → 実装 → 装置）。PART II 第 32-35 話で 4 層を順に展開、それ以降の PART は規範主層を厚く扱う。

第三軸: **担い手軸**（Mediator → Introvert Thinker → 翻訳者型 → 自己言及運営型）。PART IV で集中的に展開し、他 PART でも各話末で当該偉業・問いの中核担い手を明示する。

## 8. 編集体制提案（kurashi-team 構造の応用）

### 8.1 全体構造

kurashi-team v0.5（planner → researcher + web-researcher → writer + deeper → editor → publisher の 7 エージェント）の系を本連載に応用しつつ、本連載独自の二点を追加する。第一に、Phase A/B/C/D 成果物への横断アクセスを担う「db-archivist」を加える。第二に、全 100 話の連載通底物語を保持する「director」を加える。

```
director               ― 連載全体の物語アーク保持・100 話単位の再調整
db-archivist           ― 31+ DB と Phase A-D 成果物の横断引き
planner                ― 1 話分の EP 仕様策定
researcher (DB 統合)   ― DB エージェント群を呼び出して素材パック作成
web-researcher (Web)   ― Web 補完リサーチ（直近 2-3 年論文）
writer                 ― 本文 1,500 字
deeper (学術の視点)    ― 学術の視点 400 字（writer と異なる学術背景）
editor                 ― A/B/C 評価ゲート + 引用検証
publisher              ― 公開・反映確認
sentinel (任意)        ― PART 終了時の品質ゲート
```

### 8.2 各エージェントの役割

**director**: 連載全体（100 話）の物語アークと PART 構造を保持する。新規話の制作前に「この話が物語アークのどこに位置するか」「他話との重複・類似はないか」を判定する。kurashi の director に相当する役割を本連載で独立させる。

**db-archivist**: 31+ DB（FK / CLA / SI / great_actions / era_talents / academic_knowledge / philosophy / lit / myth / TK / 他）と Phase A-D 成果物（72+ HTML / 30+ MD）への横断検索を担う。新規話のリサーチ起動時、まず db-archivist が「この話で引くべき DB トップ 5 + Phase 成果物トップ 3」を提示する。

**planner**: kurashi-planner と同様に 1 話分の EP 仕様（タイトル候補・構造・主軸 DB・出典候補・要素間接続）を作成。本連載独自の追加要素として「物語アーク内位置」「前話・後話との連結」「PART 内テーマとの整合」を必ず含める。

**researcher**: DB エージェント群（academic-oracle / signal-db / si-framework / philosophy / lit / myth / traditional-knowledge / 他）を呼び出して素材パックを作成。EP 仕様の主軸 DB に応じて呼び出すエージェントを変える。

**web-researcher**: kurashi-web-researcher と同様に Semantic Scholar / WebFetch を組み合わせて、DB だけでは拾えない直近 2-3 年の論文・統計を補完。DOI 必須。

**writer**: 本文 1,500 字を執筆。冒頭多様化原則・二人称使用ガイドライン・術語最小化を厳守。

**deeper**: 学術の視点 400 字を執筆。writer の学術背景と異なる別レンズを採用（事業のかたちで実証された v0.5 設計）。例えば writer が哲学レンズで書いたら deeper は人類学レンズ、writer が政治学なら deeper は文学、というように学術ペアを組む。

**editor**: A/B/C 評価ゲート（A: 公開可 / B: 軽微修正 / C: 差戻し）。引用検証（DOI/URL の二段階確認）+ 冒頭多様化チェック + 英字濃度（< 2%）+ 字数（本文 1,500 ± 100、視点 400 ± 50）+ 読みやすさ（fukugou_score）を判定。

**publisher**: articles_batchN.py に追加 → generate.py 実行 → HTML タグバランス検証 → git commit → GitHub Pages 反映確認。

**sentinel（任意）**: PART 終了時（20 話単位）に PART 全体の品質ゲートを実施。連載中盤の自己診断話 + 終話を起点に、Phase A-D 成果物との整合性を再確認する。

### 8.3 並列度と差戻し制御

```
直列: db-archivist → planner       (1 話分 1 日)
並列: researcher + web-researcher  (1 話分 1 日)
並列: writer + deeper              (1 話分 1-2 日)
直列: editor                       (1 話分 0.5 日)
直列: publisher                    (1 話分 0.5 日)
合計: 1 話分 3-4 日 / 週 1-2 話制作可能
```

差戻しは最大 2 回まで自動制御、3 回失敗は director 経由で西村氏報告（kurashi-team v0.5 仕様を継承）。

## 10. 確認事項（着手前）

連載開始前に西村勇也氏に以下 8 点を確認したい。

### 10.1 確認 1: 連載タイトル（推奨「未来のかたち」）

第一候補「未来のかたち ― 学術が未来予測の前提に出会うとき」を推奨するが、第二〜四候補のいずれを採用するかは西村氏の最終判断を仰ぎたい。「のかたち」シリーズの 5 番目として整合的だが、「未来のかたち」という言葉が既存の用法（柳田國男「明治大正史世相篇」等）と重なる可能性があり、独自性の確保について検討が必要。

### 10.2 確認 2: 配信媒体と公開先

候補は次の三つである。(a) `https://stg.miratuku-journal.org/i_academias/` の系統で `https://stg.miratuku-journal.org/i_futures/` を新設、(b) `https://yuyanishimura0312.github.io/` 配下に独立 GitHub Pages、(c) miratuku-news-v2 ダッシュボード配下のサブパス。kurashi-no-katachi が GitHub Pages、jigyo（i_academias）が miratuku-journal stg を採用しているため、本連載は (a) miratuku-journal stg が整合的だが、Phase A-D 成果物への参照頻度が高いため (c) miratuku-news-v2 配下も検討余地がある。

### 10.3 確認 3: 配信ペースと開始時期

週 4 話配信 / 25 週完結を推奨するが、週 2 話配信 / 50 週完結 / 約 1 年運用も選択肢。学びのコミュニティ Futures の月次セッションと同期する場合、月 4 話配信 / 月 1 PART 開封 / 25 ヶ月運用も可能。本連載の「学術濃度」を考えると週 2 話 / 50 週運用が読者負担を抑えるが、コミュニティ運営期間との整合は別途必要。開始時期は 2026-06 開始が制作キャパ的に妥当。

### 10.4 確認 4: パイロット 5 話の選定

Month 2 でパイロット 5 話制作を推奨するが、選定話を「第 1 / 第 2 / 第 22 / 第 41 / 第 61 話 = PART 別 1 話ずつ」として良いか。代替案として、戦略的空白特集を優先する「第 23 (G-M04) / 第 25 (G-N09) / 第 28 (G-V03) / 第 50 (中間自己診断) / 第 100 (終話)」案もある。後者は連載アークの両端 + メタ核を先にテストする利点があり、Phase D 推奨「DQ-05 G-V03 を Phase D 全体の自己診断軸として運用」と整合する。

### 10.5 確認 5: 学びのコミュニティ Futures の規模と運営体制

参加者数（30 / 50 / 100 名）、参加形態（無料公開 / 有料会員 / ハイブリッド）、月次セッションの実施形式（オンライン / 対面ハイブリッド / 対面のみ）を確認したい。連載と直接同期するため、コミュニティ規模が制作チーム編成にも影響する。100 名以上であれば Slack ワークスペースの運営担当（community-operator）の追加が必要。

### 10.6 確認 6: 既存連載との相互参照

事業のかたち（jigyo）/ 暮らしのかたち（kurashi）/ 変化のかたち（henka）/ いとなみのかたち（itonami）の 4 連載との相互参照をどの程度密に行うか。本連載は「フォーサイト × 学術」の系で、既存 4 連載とは別の射程を取るが、第 5 類型「翻訳者型」の話は kurashi（暮らし）と jigyo（事業）の系譜と重なる部分がある。重なる箇所で「本連載第 X 話と kurashi 第 Y 話を併読推奨」という相互参照リンクを設置するか否か。

### 10.7 確認 7: Phase D 完了との同期

本連載企画は Phase E:展開 2 として Phase D 完了を前提とするが、Phase D は現時点で D-0 + D-1 事前検討まで完了で、D-2 並列執筆は未着手。Phase D 完了が遅延した場合、本連載の PART II/III の素材精度に影響する。Phase D 完了予定（_PHASE_D_PLAN.md 記載）と本連載開始予定の同期点を確認したい。代替案として、PART I（Phase A 実数値中心）を先行制作し、PART II 以降は Phase D 完了確認後に本格化する二段階運用がある。

### 10.8 確認 8: 連載完了後の派生（教科書・書籍・学術論文）

連載完了後（Month 12 以降）の派生活用について方針を確認したい。候補として、(a) 100 話を 1 冊の教科書 HTML（200,000 字級、textbook.html 構造 + 赤白 CI）にまとめる、(b) 商業出版（200-300 ページ書籍）、(c) 査読付き学術ジャーナル投稿（フォーサイト分野 / 教育学分野）、(d) 派生スピンオフ連載（PART V を 100 話に拡張する 2027 年運用）。本連載は構造的に教科書化と相性が良いため、(a) を最有力候補として運用したい。

## 11. 結語

本企画書は Phase A 9 トラック + Phase B 6 トラック + Phase C 7 トラック + Phase D 4 段階 の統合知識基盤を、学びのコミュニティ Futures に向けた「読みながら考える 100 話」に翻訳する設計である。連載タイトルは推奨「未来のかたち」、構造は 5 PART × 20 話、各話 1,500 字 + 学術の視点 400 字 + 出典一覧、運用は kurashi-team v0.5 系の 7 エージェント + 本連載独自の director / db-archivist 計 9 エージェントによる /futures コマンドで実行する。

本企画書の独自貢献は四点ある。第一に、Phase B 71 問単一台帳と Phase C 140 偉業 + 担い手 5 類型を、100 話単位の連載に展開可能なテーマ構成として確定したこと。第二に、第 50 話 + 第 99/100 話を連載全体の自己診断軸として配置し、Phase D 推奨「DQ-05 G-V03 を Phase D 全体の自己診断軸として運用」を本連載で実装したこと。第三に、本連載独自の director / db-archivist エージェントを追加し、31+ DB + Phase A-D 成果物の横断引きを連載運用フローに組み込んだこと。第四に、連載完了後の派生（教科書化・書籍化・学術論文化・スピンオフ連載）の四つの選択肢を提示し、ミラツクの「対等な探究者」「知識運動体」「暗黙知の AI 形式知化」アイデンティティを 12 ヶ月運用と長期持続の両軸で実装したこと。

本企画書は西村勇也氏の確認 8 点（§ 10）の意思決定を経て、Stage 0 仕様策定 → Stage 1 リサーチ・設計 → パイロット 5 話制作 → 本格制作開始の流れで実行に移る。Phase E:展開 2 は本連載企画書の APPROVED により Stage 1 へ移行し、続く Phase E:展開 3 では学びのコミュニティ Futures の運営フレーム策定と接続する。
