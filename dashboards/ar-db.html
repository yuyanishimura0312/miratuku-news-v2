概要 — 何が入っているか

本データベースはミラツク／esse-sense エコシステムで 現在使用している全エージェント・コマンド・スキル・ルール を単一の SQLite DB に統合したものである。/adb（Academic DB Build v1.1）が方法論アドバイザーとして伴走し、データソースの確認・カバレッジ目標・cross_db_refs 設計・品質指標の三つを継承して構築した。

/adb advisor note — 概念DBではなく実データDBであるため、Phase 0-15 の中から特に Phase 1（ETL設計）・Phase 3（cross_ref整備）・Phase 13（品質メタ）・Phase 15（年次自動更新）の四点を継承した。Phase 4-12（多言語拡張・系譜chain・narrative生成等）は学術概念固有のため適用外と判定。

  • Tier 3 Utility: 単純な参照・コマンド・スキル・ルール

方法論 — /adb 伴走の三継承

/adb advisor briefing — 本DBは実データDB（経路B）として構築したが、量100%目標／cross_ref網／品質メタの三軸は /adb の Phase 1-3-13 から継承した。以下は具体的継承点。

継承1: Phase 1 ETL設計（量と多様性の両立）

/adb Phase 1 で繰り返し直面した「フロントマター欠落」「同名重複」「YAML パース失敗」の3問題を、本DBでも事前想定して設計した。複合キー (name, agent_type) によりエイリアス衝突を許容し、frontmatter 欠落も has_frontmatter フラグで明示記録する。

継承2: Phase 3 cross_db_refs（生態系への接続）

本DBは独立した島ではなく、db-registry.json／miratuku-news-v2 dashboards／MEMORY.md／claude-memory-sync の四基幹システムと cross_db_refs で結ばれている。これにより「新エージェント追加 → MEMORY.md 更新 → 同期 → 本DB再ETL」のループが構造的に成立する。

継承3: Phase 13 品質メタデータ（数値で語る）

_quality_metadata テーブルに 12指標を格納し、いつでも目標値との対比でDBの健康状態を診断できる。/ddb（Deep DB Diagnostic）と統合可能な形式（3軸：Variety/Volume/Quality）で記録した。
