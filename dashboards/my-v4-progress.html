00概要

v4 は MY神話DB の neue Phase である。v3 では構造（Glottolog/D-PLACE紐付け、GTAコーディング、F4系譜分析、F5神話社会レイヤー）を完成させた。v4 では neue Phase として「神話本体の体系的拡大」に焦点を移す。narratives 11,906件 → 30,000件、文化数 671 → 900、過少代表地域（Americas/Oceania/Africa）を最大10倍規模に拡張することを目指す。

計画は7フェーズ（G0基盤整備 + G1北米 + G2中南米 + G3サブサハラ + G4オセアニア + G5北極圏 + G6東南・南・中央アジア + G7欧州周縁）の並列実行である。各フェーズに独立した収集チームを配置し、Internet Archive PD ethnographies を主軸とする。本ダッシュボードは初日のパイロット完了状況を記録する。

04パイプライン実証

v4 のパイプラインは IA メタデータAPI → djvu.txt → 6段階validation gate → DB ingest の一気通貫である。20件のパイロット収集すべてが validation gate を通過し、DBに正しく登録された。これは v3 の F1-2 sacred_texts で 17/24 が破損したのとは対照的で、validation gate の設計は当初の目的を完全に達成している。

各フェーズの収集チームから 4 つの重要な運用知見が得られた。第一に、IA の `inlibrary` / `printdisabled` コレクションは djvu.txt メタデータが見えても本文ダウンロードが 401/403 になるため、メタデータの `collection` フィールドで事前判定する必要がある。第二に、`americana`、`gerstein`、`cornell`、`wellcomelibrary`、`europeanlibraries`、`gutenberg`、`opensource`、`toronto` 系のコレクションは安定して PD コンテンツを返す。第三に、植民地時代民族誌は culture 表記が現代 Glottolog と異なる場合がある（Maasai/Masai、Buganda/Baganda、Inca/Yncas、Arrernte/Arunta）。これは v4_culture_aliases テーブルで管理する。第四に、IA APIコール数は 1ターゲット平均 2-3 回（検索 + メタデータ + テキスト）で、レート制限内で安定する。

06次のステップ

6つのパイロットチーム全てが 5/5 で完了し、全30件が validation gate を通過してDBに登録された。100%のパイプライン成功率は、IA メタデータAPI → djvu.txt → 6段階validation → ingest の運用が安定確立したことを示す。次のステップは三層構造である。

第一に、各フェーズの本格収集を実行する。優先キューには合計 115文化、2,909件のギャップが登録されており、これを順次拡充する。30件のパイロットで 29.2M字のテキストが追加されたことを踏まえると、本格収集では数十倍の規模が見込まれる。第二に、累計narratives が 15,000 を超える時点で F4 系統発生分析を再走し、Mantel 検定の精度、新規文化を含む Newick 系統樹、F5 narrative_society_links を更新する。第三に、Chukchi、Yakut、Buryat 等の北東シベリア神話のように IA上のPDテキストが極めて少ない地域については、Hathitrust や Project Gutenberg の txt 形式直接取得経路を v4_collect.py に追加する（G5チームから提案あり）。

v4 完了は当初 10 週間を見込んでいたが、パイロットが想定よりはるかに高速・高品質に進行したため、6-8 週間での完了が視野に入る。費用見積は LLM API 約 $100-150（v3 実績ベース）、インフラ追加コスト $0、外部サービス料金 $0 である。

本ダッシュボードは v4 進捗トラッカー。最新の自動メトリクスは v4_progress テーブルから取得可能。30件のパイロット完了をもって、v4 は本格収集フェーズへ移行する。
