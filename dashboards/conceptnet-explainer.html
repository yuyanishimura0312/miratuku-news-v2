CHAPTER 01

ConceptNet とは何か

ConceptNet は、人間が当たり前に持っている「常識（commonsense）」を、コンピュータが扱える形のグラフに変換した知識基盤である。「鳥は飛ぶ」「コーヒーは熱い」「医者は病院で働く」── こうした、辞書には書かれないが誰もが知っている関係を、3,400 万本のエッジで結んでいる。

もう少し技術的に言えば、ConceptNet は 多言語の semantic network（意味ネットワーク）である。ノード（node）は単語や短いフレーズで、エッジ（edge）はノード同士を「使う / である / 部分である / 引き起こす」といった関係でつなぐ。たとえば cat ─ /r/IsA ─ animal（猫は動物である）、knife ─ /r/UsedFor ─ cutting（ナイフは切るために使われる）といった具合である。

WordNet（プリンストン大学の語彙データベース）が「同義語の集合（synset）」を中心に据えるのに対し、ConceptNet は 関係そのもの を中心に据える。WordNet が「cat と feline は同義だ」と教えるとすれば、ConceptNet は「cat は牛乳が好きだ / 夜行性だ / ペットとして飼われる / ネズミを捕る」と教える。前者が辞書、後者が常識集と言ってもいい。

本レポートの読み方
このレポートは、ConceptNet 自体を初見の読者でも理解できるよう書かれている。第 1〜7 章で ConceptNet の構造と到達点を把握し、第 8 章で限界、第 9〜10 章で本エコシステム（AR-DB + 167 DB）が立つべきベンチマークを定義する。
CHAPTER 02

27 年の歴史 ─ OMCS から ConceptNet 5.8 へ

ConceptNet の起点は、1999 年に MIT Media Lab で立ち上げられた Open Mind Common Sense (OMCS) プロジェクトである。Push Singh と Marvin Minsky が中心となり、「インターネット上の不特定多数のボランティアから常識を集める」という、当時としては大胆な試みだった。

2007 年頃から MIT の研究者 Robyn Speer（後の Luminoso Technologies 共同創業者）が中核を担うようになり、2017 年の AAAI で発表された ConceptNet 5.5: An Open Multilingual Graph of General Knowledge によって学術的にも産業的にも広く認知される基盤になった。

主要マイルストーン

  • 1999MIT Media Lab が Open Mind Common Sense (OMCS) を立ち上げ。Push Singh / Marvin Minsky 主導。ボランティアから英文の常識を集める Web フォーム方式。
  • 2007初期版 ConceptNet 公開。100 万本程度のエッジ。
  • 2012ConceptNet 5 リリース。多言語化を本格化。LREC 2012 で論文発表。
  • 2017ConceptNet 5.5 リリース、AAAI で論文発表。Numberbatch（後述）が SemEval-2017 Task 2 で総合優勝、複数言語で state-of-the-art を達成。Luminoso Technologies が運用主体に。
  • 2019ConceptNet 5.7 リリース。REST API（JSON-LD）の整備。
  • 2020ConceptNet 5.8 リリース（最終版）。インドネシア語・マレー語独立。Wiktionary パーサ更新。HTTPS / Jenkins / Terraform 整備。
  • 2021Robyn Speer が Luminoso を退社。9 月以降 PyPI 更新停止。事実上の maintenance mode 入り。
  • 2026conceptnet.io の API は稼働中。ただし新規エッジ追加は停止状態。Robyn Speer の活動は concepts.arborelia.net に移行。

つまり、ConceptNet は 27 年の歴史を持ち、技術的には完成形に近く、しかし新規拡張は事実上止まっている ── これが 2026 年現在の正確な姿である。

CHAPTER 03

エッジ数 3,400 万、ノード数 約 800 万、扱う言語は 304 にのぼる。ただしこの「304 言語」の中身は不均一で、英語・フランス語・ドイツ語・日本語・中国語など コア 10 言語が大半のエッジを占め、中程度 77 言語と残り 217 言語は Wiktionary 由来の辞書的エッジが中心になる。

関係タイプは 34 種に絞られている。これは「設計思想として汎用的な関係だけを許す」という選択の結果で、後述するように Wikidata の 12,000 プロパティとは方向性が大きく異なる。

CHAPTER 04

34 の関係タイプ ─ 何を「常識」として保持するか

ConceptNet が扱う 34 の関係タイプ（/r/ namespace）は、人間の常識を 34 種類に整理した分類体系として読める。代表的なものを挙げる。

意味の関係

  • /r/Synonym ─ 同義（happy ⇄ joyful）
  • /r/Antonym ─ 反対語（hot ⇄ cold）
  • /r/SimilarTo ─ 類似（cat ≈ tiger）
  • /r/DistinctFrom ─ 区別される（red ≠ blue）

分類・所属の関係

  • /r/IsA ─ 〜である（dog → mammal）
  • /r/PartOf ─ 〜の一部（wheel → car）
  • /r/HasA ─ 〜を持つ（car → wheel）
  • /r/MadeOf ─ 〜でできている（bread → flour）

機能・目的の関係

  • /r/UsedFor ─ 〜のために使う（knife → cutting）
  • /r/CapableOf ─ 〜できる（bird → fly）
  • /r/HasProperty ─ 〜の性質を持つ（ice → cold）
  • /r/Desires ─ 〜を欲する（cat → fish）

事象・因果の関係

  • /r/Causes ─ 引き起こす（rain → wet）
  • /r/HasSubevent ─ サブイベント（cooking → cutting）
  • /r/HasPrerequisite ─ 前提条件（drive → license）
  • /r/MotivatedByGoal ─ 目的（study → learn）

位置・文脈の関係

  • /r/AtLocation ─ 典型的な場所（fish → water）
  • /r/LocatedNear ─ 近くにある
  • /r/HasContext ─ 〜の文脈で（home run → baseball）

語源・形態の関係

  • /r/FormOf ─ 活用形（running → run）
  • /r/DerivedFrom ─ 派生（unhappy ← happy）
  • /r/EtymologicallyRelatedTo ─ 語源的関連

残りには /r/RelatedTo（最も汎用な「何らかの関係がある」）、/r/SymbolOf（象徴）、/r/CreatedBy（作者）、/r/ReceivesAction（受動）、/r/MannerOf（やり方）などが含まれる。

設計思想 ─ 「34 種で足りる」という割り切り
Wikidata がプロパティを 12,000 種類用意するのに対し、ConceptNet は 34 種で割り切る。これは「常識は汎用関係で十分に表現できる」という思想の選択である。深い専門知識（「タンパク質 X はパスウェイ Y に属する」など）は扱わず、「コーヒーは熱い」のような誰もが知っている関係に絞る。本エコシステムが領域別に関係タイプを正規化する設計（学術概念 DB の predecessor / successor / cross_domain 等）とは方向性が真逆である。
CHAPTER 05

8 系統のデータソース ─ どこから常識を集めたか

ConceptNet 5.8 のエッジは、以下の 8 系統から供給されている。供給割合が大きい順に挙げる。

① Wiktionary（最大シェア）

多言語辞書 Wiktionary から自動抽出された同義語・反意語・翻訳・語義。ConceptNet の多言語性のほとんどは Wiktionary に依存している。2020 年版（5.8）では、フランス語・ドイツ語 Wiktionary を 4 年分更新した。

② Open Mind Common Sense (OMCS)

1999 年に MIT で立ち上げられた、ConceptNet の母体。Web フォームで一般ボランティアから「○○ は △△ のために使う」のような英文を集めた。後述する ノイズの主要発生源でもある。

③ Open Multilingual WordNet (OMWN)

WordNet を 30 以上の言語に拡張した専門家構築の語彙ネットを統合。同義語と分類関係（IsA）の精度が高い供給源。

④ DBpedia

Wikipedia のインフォボックス（記事右上の構造化部分）から自動抽出された関係。「人物の出身国」「映画の監督」など事実的関係を補強。

⑤ OpenCyc

Doug Lenat が 1984 年から構築している大規模オントロジー Cyc の公開部分。形式論理に近い厳密な分類関係を提供。

⑥ JMDict

日本語の電子辞書プロジェクト。日本語ノードの主要供給源。

⑦ Games With A Purpose (GWAP)

クラウドソースをゲーム化した試み。代表は CMU の Verbosity（英語）と日本の nadya.jp（日本語）。プレイヤーが楽しみながら知識を入力する仕組み。

⑧ 一部の専門辞書

業界・ドメイン辞書のごく一部が統合されている。

供給源の偏りが、後述する限界を生む
ConceptNet の供給源は OMCS（英語クラウドソース）+ Wiktionary（多言語辞書）が二大柱である。これは「英語常識を中核に、多言語へ辞書的に展開する」という構造を必然的に持つ。後述する Eurocentric な偏りはこの供給源構造に由来する。
CHAPTER 06

API と利用方法 ─ どう使うか

ConceptNet は REST API（JSON-LD 形式） で誰でも利用できる。3 つのクエリ方法がある。

① Lookup ─ 概念名から関連エッジを取る

GET http://api.conceptnet.io/c/en/football

"football" に関連するエッジ群を JSON で返す。日本語は /c/ja/...、トルコ語は /c/tr/...。

② Search ─ 条件にマッチするエッジを探す

GET http://api.conceptnet.io/search?rel=/r/UsedFor&end=/c/en/cutting

「切るために使われるもの」を全部返す（knife, scissors, saw など）。

③ Association ─ 概念に「近い」概念を見つける

GET http://api.conceptnet.io/related/c/en/cat?filter=/c/en

"cat" に意味的に近い英語概念を返す（dog, kitten, feline など）。Numberbatch 埋め込みベース。

CHAPTER 07

Numberbatch ─ ConceptNet が NLP の標準になった瞬間

ConceptNet を一躍 NLP（自然言語処理）の主流に押し上げたのが、ConceptNet Numberbatch という派生プロダクトである。

Numberbatch は 単語埋め込み（word embeddings）、つまり「単語を数百次元のベクトルで表現する」技術である。Google の word2vec、Stanford の GloVe と並び、2017 年時点で 最も精度の高い単語埋め込みと見なされた。

仕組み

Numberbatch は単独のモデルではなく、複数の手法を組み合わせた アンサンブル である：

  • word2vec（Google）の分散表現
  • GloVe（Stanford）の共起ベース埋め込み
  • OpenSubtitles 2016（映画字幕コーパス）
  • これらを ConceptNet のグラフ構造で retrofitting（再調整）する

つまり「統計的に得た埋め込みを、ConceptNet が知っている『これとこれは意味が近い』という常識で補正する」発想である。

SemEval-2017 Task 2 ─ 「多言語意味類似度」での圧勝

2017 年の SemEval（自然言語処理の国際コンペ）Task 2「多言語・言語横断的な意味類似度」で、Numberbatch は landslide victory（圧勝）を記録した：

  • 2 つのサブタスク両方で 1 位
  • 5 言語中 4 言語で 1 位
  • 10 の言語横断ペア全てで 1 位

これによって ConceptNet は単なる「常識データベース」を超えて、実用 NLP の基盤技術 として広く採用されるに至った。質問応答・意味検索・分類タスクなどで世界中の研究者・企業が使っている。

本エコシステムに引き寄せて
本エコシステムには Numberbatch に相当する 横断的な埋め込みレイヤ がまだない。AR-DB はメタ層を持つが、167 DB の概念を「ベクトル空間で意味的に近い概念を瞬時に返す」機能は実装されていない。これは追うべき機能ベンチマークの一つである。
CHAPTER 08

知られた限界 ─ ConceptNet の弱点

ConceptNet は 27 年の蓄積を持つ強力なリソースだが、学術文献では複数の限界が指摘されている。これらは 本エコシステムが構造的に避けている / 既に超えている領域 でもある。

① ノイズが多い

OMCS のクラウドソース文が未検証で混入している。WWW 2019 の論文 "Predicting ConceptNet Path Quality" は、「ConceptNet の関係パスの多くは非常識的（non-sensical）であり、単純なヒューリスティクスではランダム選択さえ上回れない」と報告している。

② 自己評価が「vague, illogical, useful」

公式 FAQ が "vague, illogical, and incredibly useful"（曖昧、非論理的、しかし非常に有用）と認めている。設計思想として厳密性より実用性を優先した結果である。

③ 文脈依存性を扱えない

「鳥は飛ぶ」は典型的には真だが、「ペンギンは飛ばない」「夜の鳥は寝る」など 条件付きで真 な常識を構造的に扱えない。Yejin Choi らの ATOMIC（2019）が「if-then」型常識でこの欠点を埋めようとした。

④ 粗い意味分離

"watch"（時計 / 見る）の名詞 / 動詞は分けるが、「中世の watch（夜警）」のような細かい語義は分けない。WordNet の synset とは設計思想が異なる。

⑤ カバレッジが不均一

FAQ 自身が "coverage of commonsense topic areas is still patchy" と認める。日常会話領域は厚いが、専門領域や非西洋文化圏は薄い。

⑥ IRR（Inter-rater Reliability）の DB 単位非公表

知識項目の品質をアノテータ間で測る Cohen's Kappa などの定量的品質指標が DB 単位で公開されていない。これは個別研究で部分的に測定された例があるのみで、本エコシステムが PHYS 0.87 / CEH 0.99 / ES 0.96 などを DB 単位で公表しているのとは対照的である。

⑦ Eurocentric な偏り

OMCS + 英語 Wiktionary + WordNet を中核とするため、多言語といっても英語スキーマの翻訳的拡張に留まる。日本の「もったいない」「いき」「気配」のような独自概念、Ubuntu のようなアフリカ哲学概念は、ConceptNet 上では英訳の薄いノードとしてしか存在しない。本エコシステムが非西洋率を 16-88%（領域別）で構造的に測定するのとは対照的である。

⑧ メンテナンス停滞

2021 年 9 月以降、PyPI 更新が止まっている。データ自体は使えるが、新しい概念（生成 AI、新興技術）はほぼ追加されない。

CHAPTER 09

共通点

  • オープン：ConceptNet は CC BY-SA、本エコシステムは GitHub private + 一部公開

暫定ベンチマーク・ステートメント

本エコシステムが立つべきベンチマーク

ConceptNet が 27 年で構築した 3,400 万エッジの汎用常識グラフに対し、本エコシステムは 51 日で 380 万エッジ（11%）を達成した。比較すべきは「規模」ではなく、ConceptNet が 27 年間構築してこなかった「品質保証された専門知識の動的合成可能性」である。

ConceptNet の規模は 2-3 年で量的に追いつき得る射程にあり、同時に IRR 公表・自己観察メタレイヤ・領域別正規化・非西洋率測定・エージェント駆動 の 5 点で構造的優位を保持する ── これが本エコシステムの benchmark statement である。

次に比較すべき外部対象

ConceptNet との比較で見えた優位を踏まえると、次は以下と比較すべきである：

  • CSKG（USC ISI, 2021）：ConceptNet + ATOMIC + Wikidata-CS + WordNet + Roget + Visual Genome を統合した 6 ソース統合 KG。「事前統合 vs 動的統合」の比較
  • ATOMIC（AI2, 2019）：因果的常識（if-then 知識）への特化。本エコシステムの genealogy_chain との対応
  • Wikidata：1.15 億エンティティの超大規模 KG。規模で大差、品質指標と非西洋率では同等以上を狙う
  • OpenAlex：2.5 億学術 work / 30 億関係。学術論文ドメインでの cross_db 接続性で比較
  • CrewAI / AutoGen：マルチエージェント・アーキテクチャ。エージェント数・連携密度で大幅超過
