01.概要と目標

本DBの目的・スコープ・到達基準

AAG-DB は、売れるアプリ・人が集まるアプリを支える学術知識を、単なる事例集ではなく多面的・精緻に集積する基盤として構築されている。16 サブフィールド (成長獲得・定着・UX・視覚デザイン・ゲーミフィケーション・行動経済・ネットワーク効果・レコメンド・マネタイズ・オンボーディング・コミュニティ・分析実験・ブランド物語・アクセシビリティ・モバイル特化UX・AI生成UX) を縦糸に、概念・関係・系譜・研究者・文献・特殊テーブル (色・フォント・パターン・事例・算法・数式・指標・ヒューリスティック) を横糸として網羅する。

Production 目標は概念 5,500・関係 20,000・クロスDB参照 18 DB 以上・出典URL 100%・検証率 95% 以上・多言語率 30% 以上・非西洋率 20% 以上・女性研究者比 15% 以上・評価者間一致 Gwet AC1 0.80 以上。

08.構築方法論

Phase 0-15 の世界最高品質パイプライン

本DBは /academic-db-build v1.1 (省略名 /adb) 経路A・Phase 0-15 で構築されている。Phase 2 ETL は 4 wave 並列 db-concept-builder + 特殊テーブル並列 + 算法/数式並列の 6 並列体制。各エージェントは 10 件毎の seed JSON バッチ保存により usage limit 到達でもデータ救出可能。primary_source_url 100%・OpenAlex / Semantic Scholar / arXiv / ACM / IEEE / NN Group / Material Design / Apple HIG / WCAG / forentrepreneurs / a16z / Mixpanel benchmarks など実在ホワイトリストのみを使用。

後続フェーズ: Phase 3 Validate (重複・欠損・異常値) / Phase 4 Relations (predecessor/successor/extends/refutes) / Phase 5 Dashboard / Phase 6 doc-verify (4大品質問題) / Phase 7 Publish (GitHub + AR-DB 自動同期) / Phase 8 Audit (ak-quality-auditor) / Phase 10 Codex 並列深堀り / Phase 11 反復 / Phase 13 IRR Gwet AC1 / Phase 14 18 DB cross_ref / Phase 15 Negative space。
