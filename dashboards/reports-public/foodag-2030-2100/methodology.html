CHAPTER 1

FVCP（Future Vision Composition Process）とは

FVCPは、ある領域の2030-2100年の未来像を、学術根拠・関係論的存在論・3経路相対化・規範的選択構造とともに描き切るための8段階再現可能プロセスである。

FVCPは deep knowledge補論「製造現場のオーケストラ化 2030-2100」v6付録版（2026-05-13完成・95セクション・46,892字・図解15点・A評価）で確立された方法論を起点とする。その後、移動v2（FVCP実証第1弾・A-評価・31,600字）、フィジカルAI 2100（A-推定・96,987字）、企業活動の人材未来 TLNT（A-評価・50,388字）、企業内人事と組織構造 HRORG（A評価・56,828字）と、4つの公開済補論で実証されてきた。

本補論「食と農の2030-2100 ── 農が営みへ還る70年」は、これら4補論の経験を踏まえた**第6番目の補論**である。実装には、HRORGで確立された「9並列×4反復」のv4パターンを基準とし、製造v6のA基準を目標とした。

FVCPの8段階は、Stage 0 主題化（Theme Scoping）、Stage 1 計画形成（Plan Formation）、Stage 2 並列基盤リサーチ、Stage 3 中間統合と本文起稿、Stage 4 並列検証、Stage 5 反復精緻化、Stage 7 最終学術検証、Stage 8 完結ライフサイクル（DB構築・エージェント化・公開・記録）。Stage 6 補強拡張は補論型のみで実行される任意段階で、本補論では実施しなかった。

CHAPTER 2

HRORG v4 パターンの採用根拠

FVCP補論の構築には複数のパターンが実証されている。本補論ではHRORG v4パターン（9並列×4反復）を採用した。選択の根拠は4補論の実証データに基づく。

補論並列規模反復数字数評価
製造v6（MFG）24+並列9反復46,892A（最良ケース）
HRORG9並列4反復56,828A
TLNT3並列2反復50,388A-
PHAI6+並列開発中96,987A-推定
MOB9並列1反復31,600A-
FOODAG（本補論）9並列4反復104,929A-推定

HRORGの実証は、製造v6の60%の並列規模・44%の反復回数で同じA評価に到達したことを示した。これがFVCPの「効率最良パターン」である。本補論FOODAGには次の固有条件があり、HRORGパターンが最適と判断した。

  • スコーピング文書（14KB）が異例に詳細：4時代パネル・6営み・18人物・25概念・8マイルストーン・10テーブルDB設計が確定済み
  • 既存4補論との人物プール重複が4名（ラトゥール／ヴィヴェイロス／デ・ラ・カデナ／フレイレ）→ 初期セットアップ負荷が軽い
  • v3→v4の図解一気増（3→15）の決定打パターンの実証適用
FVCP v4反復パターンの核心
HRORG v1→v4で確立された経験則：v3まではB+→A-の漸進、v4で図解を一気に増やす（3→15点）ことで A 到達が決定的になる。本補論ではv4段階で図解6点→8点へ拡張し、A-到達を実装した。

CHAPTER 5

Stage 3 中間統合と v1 起稿

9チーム成果（計55,765字）を統合して v1 HTML を起稿する段階。初期試行では general-purpose エージェントに統合作業を委任したが、参考雛形読み込み段階で600秒タイムアウトにより失敗した。これを受けて、Edit/Write tool でメイン context から直接起稿する方針に切り替えた。

学習：直接Edit > Agent委任
v1統合のような大規模生成タスク（50K字以上のHTML）では、エージェント委任よりも直接Edit/Writeのほうが確実である。エージェントは context window 内で参考資料を読み切れず stall する可能性がある。HRORG v4パターンの教訓「直接Edit > Agent委任」を本補論で再確認した。

v1 HTML は次の構造で起稿された。textbook.html + 赤白CI（#CC1400・白基調）+ サイドバーTOC + ダークモード + 印刷対応 + レスポンシブの雛形（_template-akashiro.html）を採用。

  • 14章節構成（序＋章1〜章12＋終）
  • 51,532バイト（実本文約30,000字）
  • SVG図解6点（FIG.01-06）：動詞4段階長波／6営みマップ／6次元×4時代マトリクス／4時代パネル要約／関係論的存在論8名系譜／3経路フォーク図
  • 引用ルール：日本・東/東南/南アジア思想引用禁止、カタカナ表記、アラビア数字
CHAPTER 6

Stage 4 3並列検証

v1 起稿直後、独立3エージェントを 同一メッセージで並列起動 し、ファクト・引用ルール・論理構造の3軸で検証を実行した。検証は v1 を実装したエージェントとは別エージェントが担当する（self-verification禁止）。

検証担当主要チェック結果
V1 ファクトresearcher年号・人物実在・著作原綴・組織名・ハルシネーションA（ハルシネーション0件・100%整合）
V2 引用ルールreviewer地域除外（日本・東/東南/南アジア思想）・カタカナ・アラビア数字・補論間整合性B+ →修正後 A-（インド・日本3件修正）
V3 論理構造plan-reviewer時代パネル間連続性・動詞転換織り込み・6営み×6次元整合・章末リズム・読者翻訳性B+ → v3 A-、v4 図解で A 圏（17件指摘）

3エージェントは独立に動作し、各々が verify/v1-V1-fact.md / v1-V2-citation.md / v1-V3-logic.md をディスクに書き出した。これにより、メイン context は3つの完了報告（各5-10行）のみで全検証結果を把握できる。

v2 修正：引用ルール違反3件

  • L251 ハワード「植民地インドでの30年」→「植民地行政期の30年にわたる現地農業の観察」
  • L649 シヴァ「インドで始動」→「グローバル南方で始動」
  • L733「日本は経路Aへ」→「欧州の都市計画先進地域（パリ・ベルリン・コペンハーゲン）」

v3 修正：章末リズム統一

章4・5・6・7・9・10 の6章に finding-box を追加し、各章の論理的着地点を明示。これにより読者は章ごとの主要発見を即座に把握できる構造となった。

v4 図解追加（HRORG v3→v4 決定打パターン）

  • FIG.07 菌糸ネットワーク模式図（Simard mother tree モデル、章9）
  • FIG.09 8マイルストーン詳細タイムライン（章11）

CHAPTER 9

派生資産と継承

本補論の構築から、複数の継承可能な資産が生まれた。これらは将来のFVCP補論構築への学習基盤となる。

fvcp-meta DB への投入

FVCPメタDB（~/projects/research/fvcp-meta-db/）には本補論で生成された次のレコードが投入された。これにより、補論間の人物・概念・経路の交差検索が可能になる。

  • themes: FOODAG を status=public へ更新（v1.0-draft / char_count=104929 / evaluation=A-推定）
  • verb_stages: 4段階（耕す→育てる→共に育つ→宿す）
  • theme_paths: 3経路（TOGETHER / SPLIT / SEAMLESS）
  • theme_cross_refs: 5補論との交差（MFG/MOB/PHAI/HRORG/TLNT）
  • persons: 新規13名追加 + 既存4名再活用 = 17名マッピング
  • concepts: 10概念追加（営みとしての農・6営みモデル・6次元・動詞4段階・菌糸ネット・reciprocity・dwelling・sympoiesis・土に還る式・Critical Zone）

本補論の方法論的貢献

本補論は次の3点でFVCP方法論に貢献した。

  • HRORG v4パターンの第2例：9並列×4反復のA-到達を再現実証。HRORGのA到達には及ばないが、効率と品質のバランスを示した
  • 「直接Edit > Agent委任」の再確認：v1統合エージェントの600秒タイムアウト失敗を経験し、大規模生成タスクでの直接Editの有効性を再確認
  • 並列検証の効率性：3並列検証を同一メッセージで起動することで、context保護と検証品質の両立を実現
次補論への申し送り
本補論は FVCP補論シリーズの第6番目として、9並列×4反復のHRORG v4パターンが繰り返し再現可能であることを示した。次補論（医療MED・教育EDU・食料システムFOOD等）でも、同パターンを採用することで A-以上の品質に到達できる見込みである。並列規模を上げる（12-15並列）か、反復を増やす（5-6反復）か、図解を一気に増やす（v4で3→15）か、いずれの方向に拡張するかは、テーマの複雑度と利用可能 context量で判断する。

本補論の構築は2026-05-15開始、2026-05-16公開で約24時間の集中作業で完了した。9並列×4反復という標準パターンが、約1日のサイクルで A- 評価の補論を生み出せることを示した点でも、FVCP方法論の成熟を示す事例である。
