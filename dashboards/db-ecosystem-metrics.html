計測の概要

本ページの数値はすべて、2026-08-02 に AR-DB の db_live_stats と agents から取得した実測値である。推計・概算・過去記録からの引き写しは含まない。データベース側は 770 ファイル・6,538 テーブル・415,817,940 行・92.4 GB で、integrity 検査は全件 ok を返した。エージェント側は実体 426 体、コマンド 450、ルール 62、スキル 51、組み込み 20 の合計 1,009 である。

読み進めるうえで前提になるのは、この体系が単一の均質な集合ではないという点である。1 プロジェクトが 100 を超えるファイルに分かれることもあれば、1 ファイルが全体の 3 割近い容量を占めることもある。したがって「いくつあるのか」「どれだけ大きいのか」への答えは、何を 1 件と数えるかに依存する。以下の 2 節は、その依存の中身を具体的に示す。

02

DB数は数え方で割れる — 770 と 293

拡張子 .db の実ファイルを数えると 770、それらを束ねるプロジェクト単位で数えると 293 になる。どちらかが誤っているのではなく、どちらも実測であり、答えるべき問いが違う。容量の見積りやバックアップの設計はファイル単位でしか成立しないし、知識基盤としての広がりを語るならプロジェクト単位でなければ実態から離れる。

差はどこから生まれるか

770 と 293 の差 477 の大半は、少数の多ファイル・プロジェクトが生んでいる。とりわけ global-researcher-db は単独で 112 ファイルを占め、その中には本体 grid.db を分割した shards/grid_s1 から grid_s4 までの中間生成物が含まれる。分割の断片を独立したデータベースとして数えるかどうかが、そのまま総数の割れになる。

03

レコード数の78%はGRID 1件

全体は 415,817,940 行だが、このうち 324,293,004 行、割合にして 78% は global-researcher-db（海外研究者データ）1 プロジェクトが占める。レコード数の上位 10 ファイルはすべて GRID に属し、最大の grid.db は単体で 121,824,942 行に達する。したがって「4.16 億行」という表現は、実質的には海外研究者データ 1 件の規模を語っていることになる。

GRID を除いた 658 ファイルは 91,524,936 行・29.0 GB である。学術知の広がりや DB 群の厚みを語る文脈では、この 9,152 万行のほうが実態に近い。対外説明では両方を併記し、どちらの数字を根拠にしているかを読み手が判別できる状態にしておく。

05

読み方と再現

本ページの数値は 2026-08-02 時点のスナップショットであり、計測のたびに動く。データベースの追加、シャードの再生成、エージェントの新設や統合はいずれも日常的に起きるため、日付を外して引用すると、いずれ実態と食い違う。参照するときは必ず計測日を添える。

再現の手順

同じ数値は AR-DB を直接引くことで再現できる。データベース側は db_live_stats の最新スナップショットを、エージェント側は agents の frontmatter 由来のモデル・階層を集計する。

sqlite3 -readonly ~/projects/research/agent-registry-db/data/agent_registry.db \
  "SELECT COUNT(*), SUM(total_rows) FROM db_live_stats;"

照会にあたっては、同一プロジェクトに total_rows が 0 の行が混じることがあるため、集計時に最大値を通す。live 統計に未収載のデータベースは観測不能として扱い、推定で埋めない。

この 3 つの数字を対外に出すときの最小限の作法。DB数は「770 ファイル / 293 プロジェクト」と併記する。レコード数は「415.8M（GRID 除きで 91.5M）」と併記する。エージェント数は「426 体、うち発火観測 119 体」と併記する。いずれも片方だけを示すと、実態より大きく、あるいは小さく伝わる。
