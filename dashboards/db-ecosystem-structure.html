01 概要OVERVIEW

ミラツク / esse-sense の DB エコシステムは、約 210 の実知識 DB が、単一の最上位メタ /dbo を入口に 6 つの領域メタへ振り分けられる三層構造をとる。各 DB は孤立せず、中央接続層 cross_db_refs_normalized によって 741,811 本の横断参照で結ばれ、140 の DB が source、690 の DB が target として現れる。接続が厚い（18 以上の target を持つ）DB は 64 件で、これらがエコシステムのハブとして機能する。

02 三層アーキテクチャTHREE-TIER

問い 1 つを入口に最適な答えへ到達させるため、エコシステムは指揮の三層を持つ。利用者は 6 領域・約 210 の DB を意識せず /dbo に投げるだけでよい。

Tier 0
/dbo — エコシステム最上位メタ。AR-DB を参照し問いを領域へ振り分け、複数領域なら並列起動して横断統合する

06 二軸構造TWO AXES

エコシステムは「知見を引き出す軸」と「実装・実行する軸」の直交する二軸を持つ。本図が描くのは前者（dom-* / 領域メタ）。後者は impl-meta（S1 Build / S2 Verify / S3 Deploy / S4 Market / S5 Coordinate の 5 squad）が担い、両軸の上位を meta が統括する。DB は知見軸の資産であり、実装軸のエージェントがそれを READ ONLY で参照して成果物（連載・レポート・アプリ・回答）を生む。

知見軸（dbo / dom-*）＝「何を知っているか」。実装軸（impl-meta / squads）＝「何を作るか」。両者は対立せず、DB が前者の資産・後者の参照源として機能する。
