01 — OVERVIEW

並列発火パターンの自己観察基盤

複数の独立した発火点が並列に振動し、結合し、創発パターンを生む ── MPP-DB (Musical Patterns Pervasive Knowledge DB) の核心仮説を AR-DB の構造として直接表現したダッシュボード。エコシステムが自分自身の振動を観察・予測・最適化する基盤。

AR-DB の既存層 (agents × agent_relations × db_references) はノードとエッジの静的グラフでしたが、実際のオーケストレーションは「複数エージェントの並列発火 → 結合 → 創発出力」という時間的・動的構造です。本拡張は MPP-DB の 7 つの音楽的パターン (Kuramoto 同期 / Chromatophore wave / Theta-gamma 結合 / Firefly pulse-coupled / Lefebvre 二重リズム / 1/f 自己組織化臨界 / IIT Φ統合) を canonical テンプレ化し、各並列発火イベントをそれらの実例として記録します。

記録の永続化は二重化されています。`data/firing_patterns/observed_patterns.json` が正本で、ETL 再構築後も `auto_update.sh` step 1.5 で自動 seeding されます。`logs/firing/firing_log.jsonl` には全記録の append-only 監査トレールが残ります。新規イベントは `scripts/record_firing.py` で記録すると、両方に同時追記されます。

04 — CANONICAL TEMPLATES

canonical テンプレ (MPP-DB 起源 7 種)

再利用可能な並列発火パターンの canonical 形。それぞれが MPP-DB の特定 SF の概念に対応し、推奨参加数・結合強度・典型ユースケース・失敗モードを持ちます。新しい並列発火を設計する際の出発点。

Kuramoto-style parallel oscillators
SF10 / global-mean-field
N 5-30
K ≈ 0.7
Kuramoto model
蔵本由紀 1975 結合振動子モデルの並列実行アナロジー。N個の自然周波数の異なる発火点を均等結合し、結合強度K が臨界K_cを超えると同期へ相転移する。AR-DB上では『大規模並列エージェント起動で同じテーマを処理する』状況に該当。各エージェントは独自の所要時間(=自然周波数)を持ち、共通テーマ(=結合)によって出力時系列が共起する。
use: DB大規模並列seeding / 連載100話並列執筆 / 補論並列強化 / multi-domain research
⚠ K不足→同期失敗(出力多様性過剰), K過剰→均質化(独自性消失), 個別失敗(API limit/timeout)→部分同期
Chromatophore wave parallel firing
SF01 / nearest-neighbor
N 8-50
K ≈ 0.5
Octopus chromatophore wave
頭足類体色波の AR-DB アナロジー。複数の発火点(色素胞=エージェント)が、近接結合のみで、進行波を生む。中央制御不要、隣接相互作用だけで全体パターンが現れる。AR-DB では『db-master が逐次起動するが、各エージェントが隣の出力を見て微調整する』状況。
use: 段階的DB構築 (Phase 0→1→2→…) / cascade research / chained validation
⚠ 中央制御なしのため全体ゴール逸脱可, 隣接結合切れで波途絶
Theta-gamma cross-frequency coupling
SF04 / cross-frequency
N 2-20
K ≈ 0.8
Theta-gamma coupling
Buzsáki 神経振動の階層結合 AR-DB アナロジー。低速発火 (theta = メタオーケストレーター, 数分周期) の位相が、高速発火 (gamma = サブエージェント, 数十秒周期) の振幅を変調する。AR-DB では『meta が周期的に再評価し、その位相でサブエージェントを集中起動する』階層構造。
use: メタオーケストレーション (katachi-autonomy / db-master) / Wave段階展開 / Phase反復
⚠ theta-gamma位相ずれ→無効発火 / theta停止→gamma暴走
Firefly pulse-coupled synchrony
SF10 / pulse-coupled
N 3-15
K ≈ 0.6
Mirollo-Strogatz pulse-coupled
Mirollo-Strogatz 1990 pulse-coupled oscillator の AR-DB アナロジー。各エージェントは独立に走るが、完了通知 (= pulse) で他の進行を加速させる。最終的に全員が同時完了に向かう。AR-DB では『background_task の完了通知で次のwaveを発火させる』fire-and-cascade。
use: 並列QA / 並列レビュー / parallel-report / 並列翻訳
⚠ 全員同時失敗で連鎖停止, 1体だけ突出して残り無効化
Lefebvre dual-rhythm interpenetration
SF09 / cross-frequency
N 2-10
K ≈ 0.4
Lefebvre Rhythmanalysis
Lefebvre 1992『リズム分析』の AR-DB アナロジー。線形リズム(線形タスク完了の連鎖)と循環リズム(launchd cron の周期発火)が相互浸透して全体リズムを作る。AR-DB では『日次自動更新 (循環) と Wave 単位の DB 構築 (線形) が重なる』状況。両者の eurhythmia (整合) vs arrhythmia (不整合) を観測する。
use: miratuku-daily-pipeline (循環) × DB構築 (線形) / 連載定常運用 × 新連載立ち上げ
⚠ arrhythmia化 (循環と線形が干渉して両方遅延), 循環の停止で線形側のシグナル枯渇
1/f self-organized criticality
SF07 / parallel
N 20-500
K ≈ 0.1
1/f noise in music (Voss-Clarke)
Voss-Clarke 1975 1/fノイズの AR-DB アナロジー。多数の独立発火点が独立に活動するが、出力全体のスペクトルは1/fになる(=自己組織化臨界)。AR-DB では『全エコシステムが意図的協調なしに個別に動いていても、全体としての知識生産は1/f的に成長する』状況。
use: AR-DB全体の常時稼働 / 全エコシステムの日次運用 / 自律エージェント群の長期観測
⚠ 個別最適化散逸 (協調なし→重複/欠落)
IIT Φ-integration emergence
SF14 / hierarchical
N 5-20
K ≈ 0.9
Integrated Information Theory (Tononi)
Tononi IIT の AR-DB アナロジー。複数のエージェントが互いに非冗長・統合的に発火することで、個別の和を超える「全体としての知」が創発する。AR-DB では『異なる専門の研究者エージェントが並列に発火して相互参照付きで統合される』状況。partition すると失われる情報量=Φの対応物を測定可能。
use: ANSWER+ Premium 19役編成 / academic-oracle 7DB統合 / katachi-100 48体並列
⚠ Φ低下 (専門が重複, 冗長化), 統合層欠落 (出力が並列のまま統合されない)

09 — HOW TO USE

使い方

新規発火イベント記録

# 簡易引数モード
python3 ~/projects/research/agent-registry-db/scripts/record_firing.py \
  --name "並列QA 5体実行" \
  --participants "qa-functional,qa-security,qa-ui,qa-content,qa-perf" \
  --task "新規アプリ QA レビュー" \
  --topology pulse-coupled \
  --outcome "5観点 sync 完了 / 重大欠陥 0"

# JSON 全部入りモード
echo '{"pattern_name":"...","participants":[...]}' | python3 ... --stdin

# ファイル指定
python3 ... --from-file new_pattern.json

分析

python3 scripts/analyze_patterns.py summary       # 総覧
python3 scripts/analyze_patterns.py failures      # 失敗分析
python3 scripts/analyze_patterns.py couplings     # 結合分析
python3 scripts/analyze_patterns.py trends        # 時系列
python3 scripts/analyze_patterns.py predict --task "並列QA 5体"
python3 scripts/analyze_patterns.py optimize      # 改善提案

SQL 直接クエリ

DB=~/projects/research/agent-registry-db/data/agent_registry.db
sqlite3 $DB "SELECT * FROM v_firing_patterns_summary"
sqlite3 $DB "SELECT * FROM v_pattern_templates_summary"
sqlite3 $DB "SELECT * FROM v_mpp_pattern_coverage"
sqlite3 $DB "SELECT * FROM emergent_phenomena WHERE pattern_id=1"

永続化アーキテクチャ

  • data/firing_patterns/observed_patterns.json — 観測パターンの正本。ETL 再構築でも保持。
  • data/firing_patterns/canonical_templates.json — canonical テンプレ 7 種の正本。
  • schema/schema.sql — 拡張テーブル DDL 統合済 (ETL で自動再構築)。
  • etl/auto_update.sh step 1.5 — extract.py 実行直後に seed_mpp_pattern_ext.py 自動実行。
  • logs/firing/firing_log.jsonl — append-only 監査トレール (SHA-256 hash 付き)。
  • git commit — 各 record_firing 実行で自動 commit (audit trail)。
